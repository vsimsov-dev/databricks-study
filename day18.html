Day 18 · Evaluation & Monitoring

평가(Evaluation)와 모니터링의 중요성

모델이 시간이 지나도 잘 작동하는지 어떻게 알 수 있을까?

📅 2026년 6월 28일 ⏱ 학습 시간: 약 10분 📝 퀴즈: 5문제
개념 설명

AI/ML 모델 평가란 무엇인가?

모델을 만들었다고 끝이 아닙니다. "이 모델이 실제로 잘 작동하는가?"를 숫자로 확인하는 과정이 모델 평가(Evaluation)입니다. 평가 없이 배포한 모델은 잘못된 예측을 내놓아도 아무도 모를 수 있습니다. 특히 제조업처럼 모델 예측이 실제 공정 결정에 영향을 주는 환경에서는 평가가 필수입니다.

평가는 크게 두 가지 시점에 이루어집니다. 모델을 배포하기 전 수행하는 오프라인 평가와, 배포 후 실제 데이터로 지속적으로 측정하는 온라인 모니터링입니다.

주요 평가 지표

분류 모델(예: 불량 여부 예측)에서 많이 쓰이는 핵심 지표들을 정리합니다.

지표의미중요한 상황
정확도 (Accuracy)전체 예측 중 맞춘 비율클래스 불균형이 없을 때
정밀도 (Precision)불량이라 예측한 것 중 실제 불량 비율오탐(False Alarm)을 줄여야 할 때
재현율 (Recall)실제 불량 중 불량이라 맞춘 비율불량을 놓치면 안 될 때
F1 Score정밀도와 재현율의 조화 평균두 지표를 균형 있게 볼 때
AUC-ROC다양한 임계값에서 모델 성능의 종합 곡선임계값 설정이 불확실할 때
💡 고분자 불량 예측에서는 재현율(Recall)이 더 중요한 경우가 많습니다. 불량을 놓치는 것(미탐)이 오탐보다 훨씬 큰 손해를 유발하기 때문입니다.

MLflow를 활용한 실험 추적과 모니터링

Databricks는 MLflow를 기본 내장하고 있어, 모델 학습 실험마다 파라미터·메트릭·아티팩트를 자동으로 기록합니다. 수십 번 실험한 모델 중 어떤 게 가장 좋았는지, 시간이 지나며 성능이 어떻게 변했는지를 UI에서 한눈에 비교할 수 있습니다.

📊

실험 추적 (Experiment Tracking)

파라미터, 학습/검증 메트릭, 모델 파일을 실험마다 자동 기록합니다.

🗂️

모델 레지스트리 (Model Registry)

검증된 모델을 등록하고, Staging·Production 단계로 관리합니다.

📈

성능 추이 모니터링

배포 후 모델의 예측 정확도가 시간에 따라 어떻게 변하는지 추적합니다.

🔔

알림 및 재학습 트리거

성능이 기준 이하로 떨어지면 알림을 보내고 재학습 파이프라인을 시작합니다.

데이터 드리프트 — 왜 모델이 점점 나빠질까?

모델을 배포한 뒤 아무것도 바꾸지 않았는데 성능이 떨어지는 현상이 자주 발생합니다. 이를 모델 드리프트(Model Drift)라고 합니다. 원인은 크게 두 가지입니다.

데이터 드리프트(Data Drift)는 입력 데이터의 통계적 분포가 변하는 것입니다. 예를 들어 여름에 학습한 공정 모델을 겨울에 그대로 쓰면, 온도·습도 분포가 달라져 예측이 틀릴 수 있습니다. 컨셉 드리프트(Concept Drift)는 입력과 정답 사이의 관계 자체가 변하는 것입니다. 새로운 원재료 공급사로 바꿔 원료 물성이 달라지면 불량 발생 패턴이 바뀌게 됩니다.

핵심 용어 카드

정밀도 (Precision)
불량으로 예측한 것 중 실제 불량인 비율. 오탐(False Alarm) 최소화에 중요
재현율 (Recall)
실제 불량 중 모델이 불량으로 맞춘 비율. 미탐 최소화에 중요
MLflow
실험 추적, 모델 등록, 배포를 지원하는 오픈소스 ML 라이프사이클 플랫폼
데이터 드리프트
시간이 지나며 입력 데이터의 분포가 변해 모델 성능이 저하되는 현상
컨셉 드리프트
입력과 출력 사이의 관계 자체가 바뀌어 모델이 더 이상 현실을 반영하지 못하는 현상
📌 한 줄 요약
모델은 배포 후에도 지속적인 평가와 모니터링이 필요하며,
드리프트를 감지하면 적시에 재학습해야 신뢰도를 유지할 수 있습니다.
오늘의 퀴즈
1고분자 필름 불량 예측 모델에서 재현율(Recall)이 정밀도(Precision)보다 더 중요한 이유는?
✅ 정답: ③
불량 예측에서 미탐(실제 불량을 정상으로 예측)은 불량 제품 출하로 이어져 클레임과 손실을 유발합니다. 반면 오탐(정상을 불량으로 예측)은 추가 검사 비용 정도로 끝납니다. 따라서 재현율을 높이는 것이 더 중요합니다.
2MLflow의 핵심 기능이 아닌 것은?
✅ 정답: ①
MLflow는 실험 추적(Experiment Tracking), 모델 레지스트리(Model Registry), 모델 서빙 등을 지원하는 ML 라이프사이클 플랫폼입니다. 실시간 스트리밍 파이프라인 처리는 Spark Structured Streaming 또는 Delta Live Tables의 역할입니다.
3데이터 드리프트(Data Drift)란 무엇인가요?
✅ 정답: ④
데이터 드리프트는 모델을 학습시킨 시점의 데이터 분포와 배포 후 실제 데이터 분포가 달라지는 현상입니다. 계절 변화, 공정 조건 변경, 원재료 변경 등이 원인이 될 수 있으며, 이는 모델 성능 저하로 이어집니다.
4F1 Score를 사용하는 것이 정확도(Accuracy)보다 유리한 상황은?
✅ 정답: ②
불량이 2%뿐인 데이터에서 모든 것을 "정상"으로 예측해도 정확도가 98%가 됩니다. 이처럼 클래스 불균형이 심할 때는 정밀도와 재현율을 균형 있게 반영하는 F1 Score가 더 의미 있는 지표입니다.
5모델 배포 후 성능이 저하됐을 때 가장 적절한 대응은?
✅ 정답: ③
성능 저하의 원인(데이터 드리프트, 컨셉 드리프트 등)을 파악한 후, 최신 데이터를 포함하여 모델을 재학습하고 재배포하는 것이 표준 대응입니다. MLflow를 활용하면 재학습 전후 성능을 비교하며 체계적으로 관리할 수 있습니다.
