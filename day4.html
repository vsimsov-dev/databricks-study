DAY 4

Spark란? 왜 빠른가?

대용량 데이터를 번개처럼 처리하는 분산 처리 엔진의 비밀

📖 개념 설명
왜 Spark가 필요한가?
데이터가 수백 GB, 수 TB를 넘어가면 일반 컴퓨터 한 대로는 처리 속도가 너무 느립니다. 예전 Hadoop MapReduce는 분산 처리를 지원했지만, 모든 중간 결과를 디스크에 썼다 읽어서 속도가 너무 느렸습니다. Apache Spark는 이 문제를 "메모리 우선 처리"로 해결하여, 같은 작업을 최대 100배 빠르게 수행합니다.

🔥 Spark란 무엇인가?

Apache Spark는 대규모 데이터를 여러 컴퓨터(노드)에 나눠서 동시에 처리하는 오픈소스 분산 컴퓨팅 엔진입니다. 2009년 UC Berkeley에서 탄생했으며, SQL, 머신러닝, 스트리밍, 그래프 처리 등 다양한 작업을 하나의 통합 엔진에서 수행할 수 있습니다.

💡 비유: 주방장(Driver)이 요리사 10명(Executor)에게 역할을 나눠주면 훨씬 빠르게 완성됩니다. Spark도 이처럼 "작업 쪼개기 → 병렬 실행 → 결과 합치기"를 자동으로 처리합니다.

⚡ 왜 빠른가? — 핵심 이유 3가지

① 인메모리(In-Memory) 처리: Hadoop이 중간 결과를 매번 디스크에 저장하는 것과 달리, Spark는 중간 결과를 RAM에 올려두고 처리합니다.

② 지연 평가(Lazy Evaluation): 모든 변환(Transformation) 명령을 모아뒀다가, 실제 결과가 필요한 순간(Action)에 한꺼번에 최적화된 실행 계획을 세워 처리합니다.

③ DAG(방향성 비순환 그래프) 실행 계획: Catalyst 최적화 엔진이 최적 실행 순서를 자동으로 계산합니다.

🏗️ Spark 아키텍처 — Driver와 Executor

Driver
작업 계획·조율
↓ 작업 분배
Executor 1
데이터 처리
Executor 2
데이터 처리
Executor 3
데이터 처리
↑ 결과 반환
각 Executor는 독립된 서버(노드)에서 병렬 실행 → 합산하여 최종 결과 반환

📊 RDD, DataFrame, Dataset

RDD(Resilient Distributed Dataset)는 Spark의 가장 기본 단위로, 여러 노드에 분산된 불변 데이터 컬렉션입니다. DataFrame은 SQL처럼 다룰 수 있는 테이블 구조로 가장 많이 사용됩니다.

💡 RDD는 "정렬되지 않은 데이터 더미", DataFrame은 "엑셀 시트처럼 정돈된 테이블"입니다.

🐍 PySpark — Python으로 Spark 쓰기

PySpark를 사용하면 평소 쓰던 Python 문법 그대로 수 TB의 데이터를 분산 처리할 수 있습니다. Databricks Notebook에서는 PySpark가 기본으로 지원됩니다.

🔄 Transformation vs Action

Transformation(filter, select, groupBy 등)은 지연 평가 대상으로 즉시 실행하지 않습니다. Action(show, count, collect 등)이 호출될 때 한꺼번에 최적화되어 실행됩니다.

⚖️ Hadoop MapReduce vs Apache Spark

🐘 Hadoop MapReduce

  • 중간 결과를 디스크에 저장
  • 반복 계산에 매우 느림
  • 배치 처리 전용
  • 머신러닝 지원 어려움

⚡ Apache Spark

  • 중간 결과를 메모리에 유지
  • 반복 계산 최대 100배 빠름
  • 배치 + 스트리밍 모두 지원
  • MLlib으로 ML 내장 지원
🏭 고분자제품기술팀 실무 적용 예시

팀에서 Spark를 쓰면 이런 것들이 가능해집니다

🔬
PP·PE·EAA 원료별 물성 데이터(DSC, TGA, MFI 등) 수십만 건을 초 단위에 필터·집계할 수 있습니다.
📋
CPP 필름의 투명도·충격강도·열접착 온도를 배합 조건별로 비교할 때, PySpark DataFrame으로 다차원 조건 필터링과 통계 요약을 자동화할 수 있습니다.
⚙️
압출코팅 PP 생산 데이터를 Spark Streaming으로 이상치를 즉시 감지하는 파이프라인을 구성할 수 있습니다.
🤖
신규 배합 후보를 ML로 예측할 때, Spark MLlib으로 대용량 실험 데이터 전처리 파이프라인을 구축할 수 있습니다.

🧠 오늘의 퀴즈 — 5문제
1Spark가 Hadoop MapReduce 대비 최대 100배 빠른 핵심 이유는?
정답: ②
Spark의 핵심은 인메모리(In-Memory) 처리입니다. RAM이 디스크보다 수백~수천 배 빠르기 때문에 속도 차이가 극적으로 납니다.
2Spark에서 여러 노드에 분산 저장되는 불변의 기본 데이터 컬렉션은?
정답: ②
RDD는 Spark의 가장 기본적인 데이터 추상화입니다. Resilient(장애 복구), Distributed(분산 저장), Dataset(데이터 모음)을 의미합니다.
3Spark의 "지연 평가(Lazy Evaluation)"에 대한 설명으로 가장 올바른 것은?
정답: ③
filter(), select() 같은 Transformation은 즉시 실행하지 않고, show(), count() 같은 Action이 호출될 때 최적 실행 계획(DAG)으로 한 번에 처리합니다.
4PySpark에 대한 설명으로 가장 올바른 것은?
정답: ②
PySpark는 Apache Spark의 Python API입니다. Databricks Notebook에서 기본으로 지원되어 별도 설치 없이 바로 사용할 수 있습니다.
5Databricks에서 Spark를 사용하는 가장 큰 장점은?
정답: ③
Databricks는 Spark 클러스터 인프라를 완전히 관리해줍니다. 클러스터를 클릭 몇 번으로 생성하고 Notebook에서 바로 코드를 실행할 수 있습니다.
📝 어제 배운 내용 복습 — Unity Catalog 구조 (Catalog > Schema > Table)
1Unity Catalog의 3계층 구조(Catalog > Schema > Table)를 설명하고, 각 계층의 역할을 서술하세요.
Unity Catalog 3계층:
• Catalog: 최상위 단위. 조직/사업 부문 수준의 네임스페이스. 예: polymer_dev, safety
• Schema: 두 번째 계층. 프로젝트나 도메인 단위. 예: polymer_dev.cpp_film
• Table: 실제 데이터가 저장되는 최하위 단위. Delta 테이블 등이 위치합니다.
이 3계층으로 데이터를 논리적으로 분리하고 각 계층에 접근 권한을 부여합니다.
2Unity Catalog에서 접근 제어(Access Control)가 중요한 이유를 기업 환경과 연결하여 설명하세요.
부서마다 접근해야 할 데이터가 다릅니다. 고분자제품기술팀은 물성 분석 데이터에 접근하지만 인사·재무 데이터는 불필요합니다. Unity Catalog로 민감 데이터 보호, 감사 로그(Audit Log)를 통한 접근 이력 추적, 실수로 인한 데이터 삭제·변조 방지가 가능합니다.
3고분자제품기술팀의 데이터를 Unity Catalog로 관리한다면 구성 예시를 들어 설명하세요.
Catalog: polymer_tech
├─ Schema: raw_data — 원료 입고 데이터, 생산 공정 로그 (Bronze)
├─ Schema: processed — 정제된 물성 분석 결과 (Silver)
├─ Schema: cpp_film — CPP 필름 물성·배합 데이터
├─ Schema: battery_pouch — 배터리 파우치용 PP 데이터
└─ Schema: extrusion_coating — 압출코팅 PP 공정 데이터
4Delta Lake와 Unity Catalog의 관계를 설명하세요.
Delta Lake는 데이터를 저장하는 파일 형식(스토리지 레이어)으로 ACID 트랜잭션, 버전 관리를 제공합니다. Unity Catalog는 그 데이터에 대한 메타데이터와 접근 제어를 관리하는 거버넌스 레이어입니다. Delta Lake가 "파일 창고"라면, Unity Catalog는 "창고 목록과 열쇠 관리 시스템"입니다.
