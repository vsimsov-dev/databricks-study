Databricks Notebook과 클러스터

Python·SQL 실행 환경과 클러스터 유형 이해

⏱ 학습 시간: 약 10분 📝 퀴즈: 5문제 🔄 복습: 4문제
개념 설명

왜 Notebook이 필요한가?

데이터를 분석하다 보면 코드를 작성하고, 결과를 확인하고, 메모를 남기는 작업이 반복됩니다. 일반 코드 에디터에서는 이 과정이 파편화되어 있지만, Databricks Notebook은 코드·결과·설명을 한 화면에서 모두 다룰 수 있는 통합 작업 환경입니다.

PP·PE 물성 데이터를 탐색하거나, SQL로 배합 이력을 조회하거나, 시각화 그래프를 만들 때 모두 하나의 Notebook 안에서 처리할 수 있습니다. 결과물을 팀원과 공유하거나 자동 실행 파이프라인으로 만드는 것도 간단합니다.

Notebook의 구조 — 셀(Cell) 기반

Notebook은 셀(Cell)이라는 단위로 구성됩니다. 셀 하나에 코드(또는 텍스트)를 쓰고 실행하면, 그 아래에 결과가 바로 출력됩니다. 셀은 독립적으로 실행할 수도 있고, 전체를 순서대로 실행할 수도 있습니다.

Python 셀 1 — 데이터 로드
# PP 물성 데이터 로드
df = spark.read.table("polymer_tech.film_quality.pp_properties")
df.show(5)
✅ 출력: 테이블 미리보기 (5행)이 바로 아래에 표시됩니다
SQL 셀 2 — SQL로 집계
%sql
SELECT grade, AVG(tensile_strength) AS avg_strength
FROM polymer_tech.film_quality.pp_properties
GROUP BY grade ORDER BY avg_strength DESC;
✅ 출력: 바 차트 또는 테이블이 바로 아래에 렌더링됩니다

매직 커맨드 (Magic Commands)

셀 첫 줄에 매직 커맨드를 쓰면 해당 셀의 실행 언어를 즉시 전환할 수 있습니다. 기본 언어가 Python이더라도 특정 셀만 SQL로 실행하거나, 마크다운 문서를 렌더링할 수 있습니다.

커맨드기능활용 예시
%pythonPython으로 셀 실행데이터 처리, 시각화, ML 모델링
%sqlSQL로 셀 실행테이블 조회, 집계, 데이터 탐색
%md마크다운 텍스트 렌더링분석 보고서 설명, 제목, 표
%scalaScala로 셀 실행고성능 Spark 작업 (고급 사용자)
%sh쉘 명령어 실행파일 확인, 패키지 설치
%run다른 Notebook 실행공통 함수 Notebook 불러오기

클러스터(Cluster)란?

Notebook의 코드는 클러스터라는 컴퓨팅 자원 위에서 실행됩니다. 클러스터는 여러 대의 가상 서버(VM)가 묶인 집합으로, Notebook을 실행하기 전에 반드시 클러스터에 연결해야 합니다.

클러스터는 Driver 노드 1개와 Worker 노드 여러 개로 구성됩니다. Driver는 작업 전체를 지휘하고, Worker들은 실제 데이터를 나눠서 처리합니다.

🎬 Driver 노드
작업 계획·조율·결과 수집
Notebook과 직접 통신
↓ 작업 분배
⚙️ Worker 1
데이터 파티션 A 처리
⚙️ Worker 2
데이터 파티션 B 처리
⚙️ Worker 3
데이터 파티션 C 처리

두 가지 클러스터 유형

🔵 All-Purpose 클러스터
  • Notebook 대화형 분석용
  • 여러 사람이 동시에 연결 가능
  • 수동으로 시작/종료
  • 탐색적 분석·개발 단계에 최적
  • 비용: 상시 실행 시 비쌀 수 있음
🟢 Job 클러스터
  • 자동화 파이프라인 실행 전용
  • 작업 시작 시 자동 생성
  • 작업 완료 후 자동 종료
  • 스케줄 배치 작업에 최적
  • 비용: 사용한 만큼만 과금

Notebook의 주요 기능

🔗

버전 관리 연동

GitHub·Azure DevOps와 연동해 Notebook 변경 이력을 관리할 수 있습니다. 코드 리뷰와 협업이 쉬워집니다.

📊

내장 시각화

SQL 결과나 DataFrame을 별도 코드 없이 바 차트·라인 차트·산점도 등으로 즉시 시각화할 수 있습니다.

🤝

실시간 공동 편집

Google Docs처럼 여러 사람이 동시에 같은 Notebook을 편집할 수 있습니다. 팀 협업에 최적화되어 있습니다.

⏰

스케줄 실행

Notebook을 Job으로 등록하면 매일·매주 특정 시간에 자동으로 실행됩니다. 반복 보고서 자동화에 유용합니다.

💡 실무 팁: 클러스터는 켜두는 동안 비용이 발생합니다. 분석이 끝나면 클러스터를 종료(Terminate)하는 습관을 들이거나, 자동 종료(Auto Termination) 시간을 설정해두세요.

고분자제품기술팀에서의 활용

팀에서는 Notebook을 활용해 PP·EAA 물성 데이터를 탐색하고 시각화할 수 있습니다. 예를 들어 %python 셀에서 matplotlib으로 인장강도 분포 그래프를 그리고, %sql 셀에서 특정 조건의 배합 레코드를 조회하는 작업을 하나의 Notebook 문서 안에 정리할 수 있습니다. 완성된 Notebook을 팀 내에 공유하면 분석 과정과 결론을 함께 전달할 수 있어 기술 보고서 대용으로도 활용 가능합니다.

핵심 용어
셀 (Cell)
Notebook의 기본 실행 단위. 코드 또는 마크다운 텍스트를 담고, 독립 실행이 가능합니다.
매직 커맨드
셀 첫 줄에 쓰는 특수 명령어(%sql, %md 등). 해당 셀의 실행 언어나 동작을 전환합니다.
클러스터 (Cluster)
Notebook 코드가 실행되는 분산 컴퓨팅 자원. Driver + Worker 노드로 구성됩니다.
Driver 노드
클러스터의 중앙 조율자. Spark 작업 계획을 세우고 Worker에게 분배하며 결과를 수집합니다.
Auto Termination
일정 시간 사용이 없으면 클러스터를 자동 종료하는 기능. 비용 절감에 필수입니다.
✨ 한 줄 요약
Databricks Notebook은 Python·SQL·설명을 한 화면에서 다루는 인터랙티브 작업 환경이고,
클러스터는 그 코드를 실제로 실행하는 분산 컴퓨팅 자원입니다.
오늘의 퀴즈 — 5문제
1Databricks Notebook의 기본 실행 단위는 무엇인가요?
✅ 정답: ② — Notebook은 셀(Cell) 단위로 구성됩니다. 각 셀을 독립적으로 실행하고 결과를 바로 확인할 수 있어 탐색적 분석에 매우 효율적입니다.
2Python 기본 Notebook에서 특정 셀만 SQL로 실행하려면?
✅ 정답: ① — 매직 커맨드 %sql을 셀 첫 줄에 입력하면, 해당 셀만 SQL로 실행됩니다. Notebook 전체 언어 설정을 바꾸지 않아도 됩니다.
3All-Purpose 클러스터와 Job 클러스터의 차이로 올바른 것은?
✅ 정답: ③ — All-Purpose는 Notebook 대화형 작업에 최적화되어 여러 사람이 동시 접속 가능하고, Job 클러스터는 스케줄 실행 등 자동화 전용으로 작업 완료 후 자동 종료됩니다.
4Databricks 클러스터에서 Driver 노드의 역할은?
✅ 정답: ② — Driver 노드는 Spark의 두뇌 역할로, 작업 계획을 세우고 Worker 노드에게 파티션을 분배하고 최종 결과를 수집해 Notebook에 반환합니다.
5고분자 제품 개발 업무에서 Notebook 활용에 가장 적합한 시나리오는?
✅ 정답: ② — Notebook은 코드·쿼리·시각화·설명을 한 화면에서 다루므로, 물성 데이터 탐색처럼 반복적으로 코드를 수정하며 결과를 확인하는 탐색적 분석에 가장 적합합니다.

🔄 어제 배운 내용 복습 — Unity Catalog 구조
1 Unity Catalog의 3단계 계층 구조를 순서대로 쓰고, 각 계층이 무엇을 담는지 설명해보세요.
Unity Catalog는 Catalog(카탈로그) → Schema(스키마) → Table(테이블) 3단계로 구성됩니다. Catalog는 최상위 컨테이너로 사업 단위나 환경(dev/prod)을 구분하고, Schema는 그 안의 주제나 팀 단위로 묶는 폴더 역할을 하며, Table/View는 실제 데이터가 담긴 최소 단위입니다.
2 Unity Catalog에서 테이블에 접근할 때 사용하는 3단계 주소 형식을 예시와 함께 설명하세요.
catalog.schema.table 형식으로 점(.)을 구분자로 사용합니다.
예: SELECT * FROM polymer_tech.film_quality.thickness_measurements;
USE CATALOG와 USE SCHEMA로 기본값을 설정하면 테이블명만으로도 접근 가능합니다.
3 Unity Catalog의 권한 상속 구조를 설명하세요. Catalog 레벨에 권한을 부여하면 어떻게 되나요?
Unity Catalog의 권한은 계층적으로 상속됩니다. Catalog 레벨에 권한을 부여하면 그 안의 모든 Schema와 Table에 자동으로 적용됩니다. 반대로 특정 Schema나 Table에만 권한을 제한해 세밀하게 제어하는 것도 가능합니다.
4 고분자제품기술팀에 Unity Catalog를 적용한다면 어떤 Catalog/Schema 구조를 만들 수 있을지 예시를 들어 설명하세요.
예시 구조:
• Catalog: polymer_tech
• Schema: cpp_retort (레트로트용 CPP), cpp_battery (배터리 파우치용), transparent_pp (투명 PP)
• Tables: physical_properties (물성 데이터), formulation_records (배합 이력), quality_test (품질 시험 결과)
이 구조로 팀 내 누구나 필요한 데이터를 쉽게 찾고, Schema 단위로 접근 권한을 관리할 수 있습니다.
