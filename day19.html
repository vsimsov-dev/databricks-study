Databricks 클러스터와 컴퓨트 심화

올바른 클러스터 선택으로 성능과 비용을 동시에 잡는다

개념 설명

All-Purpose 클러스터 vs Job 클러스터

Databricks에서 코드를 실행하려면 컴퓨팅 자원인 클러스터가 필요합니다. 클러스터는 용도에 따라 크게 두 종류로 나뉩니다. 어떤 클러스터를 언제 쓰느냐가 비용과 효율에 큰 차이를 만듭니다.

🖥️ All-Purpose 클러스터
  • 대화형 노트북 작업에 최적화
  • 여러 사용자가 동시에 공유 가능
  • 수동으로 시작·종료
  • 탐색적 분석, 개발, 디버깅에 적합
  • 비용: 상대적으로 높음 (상시 대기)
⚙️ Job 클러스터
  • 자동화된 배치 작업 전용
  • 잡 실행 시 생성, 완료 후 자동 삭제
  • 단일 잡만 처리 후 종료
  • 야간 배치, 파이프라인 스케줄링에 적합
  • 비용: 낮음 (실행 시간만 과금)
💡 원칙: 개발·탐색은 All-Purpose로 편하게, 정기 배치는 Job 클러스터로 비용 절감. 이 구분만 지켜도 클라우드 비용을 크게 줄일 수 있습니다.

오토스케일링 (Autoscaling) 원리

작업 부하는 항상 일정하지 않습니다. 데이터가 적을 때는 워커 2개로 충분하지만, 대규모 분석 실행 시에는 10개가 필요할 수 있습니다. 오토스케일링은 클러스터가 현재 부하를 보고 워커 수를 자동으로 늘리거나 줄이는 기능입니다.

클러스터 정책과 비용 최적화

대규모 조직에서는 누구나 아무 사양의 클러스터를 만들 수 있으면 비용이 폭발합니다. 클러스터 정책(Cluster Policy)은 관리자가 사전에 허용 가능한 인스턴스 타입, 최대 워커 수, 자동 종료 시간 등을 규정으로 정해놓는 기능입니다. 개발자는 정책 범위 안에서만 클러스터를 생성할 수 있습니다.

💸

자동 종료 설정

비활성 상태가 N분 지속되면 클러스터를 자동으로 꺼서 방치 비용을 막습니다.

📋

인스턴스 타입 제한

고비용 GPU 인스턴스는 ML팀만 사용하도록 정책으로 제한할 수 있습니다.

📏

최대 워커 수 제한

실수로 100개짜리 클러스터를 만드는 것을 방지합니다.

🏷️

태그 강제 적용

팀·프로젝트 태그를 필수로 지정해 비용 귀속을 명확하게 추적합니다.

Spot Instance — 비용을 70%까지 절감하는 방법

클라우드 제공사(AWS, Azure, GCP)는 여유 서버를 Spot Instance(스팟 인스턴스)로 저렴하게 제공합니다. On-Demand 대비 60~80% 저렴하지만, 클라우드 제공사가 필요하면 언제든 회수(중단)할 수 있습니다. 이 때문에 중단되면 안 되는 대화형 작업에는 적합하지 않지만, 체크포인트를 사용하는 배치 잡에는 매우 효율적입니다.

🏭 고분자팀 클러스터 전략 탐색적 분석(낮 시간): All-Purpose 클러스터 1개를 팀이 공유. 오토스케일링으로 2~8 워커 자동 조정. 비활성 60분 시 자동 종료.

야간 배치 분석(새벽 2시): 전월 PP·PE·EAA 물성 데이터 집계 잡을 Job 클러스터 + Spot Instance로 실행. On-Demand 대비 약 65% 비용 절감. 잡 완료 후 클러스터 자동 삭제.

핵심 용어 카드

All-Purpose 클러스터
여러 사용자가 공유하는 대화형 노트북용 클러스터. 개발·탐색에 적합
Job 클러스터
자동화 배치 잡 전용 클러스터. 잡 완료 후 자동 삭제되어 비용 효율적
오토스케일링
부하에 따라 워커 노드 수를 자동으로 늘리거나 줄이는 기능
Spot Instance
클라우드의 여유 서버를 저렴하게 사용. 언제든 회수될 수 있으나 비용이 60~80% 저렴
클러스터 정책
관리자가 허용 인스턴스 타입, 최대 워커 수 등을 규정해 비용을 통제하는 기능
📌 한 줄 요약
개발은 All-Purpose, 배치는 Job + Spot Instance로 나누면
성능 저하 없이 클라우드 비용을 획기적으로 줄일 수 있습니다.
오늘의 퀴즈
1Databricks Job 클러스터의 가장 큰 특징은?
✅ 정답: ②
Job 클러스터는 자동화 배치 잡 실행을 위해 시작 시 생성되고, 잡이 완료되면 자동으로 삭제됩니다. 실행 시간만큼만 과금되어 비용 효율적입니다. 대화형 공유 작업에는 All-Purpose 클러스터가 적합합니다.
2고분자팀 탐색적 데이터 분석(EDA)에 적합한 클러스터 구성은?
✅ 정답: ③
탐색적 분석은 여러 팀원이 노트북으로 실험하는 대화형 작업입니다. 팀 공유 All-Purpose 클러스터에 오토스케일링으로 부하에 맞게 워커를 조정하고, 비활성 시 자동 종료 설정으로 방치 비용을 막는 구성이 최적입니다.
3오토스케일링을 사용했을 때의 장점은?
✅ 정답: ④
오토스케일링은 현재 작업 부하를 모니터링해 필요할 때 워커를 추가하고, 유휴 상태가 되면 자동으로 줄입니다. 항상 최대 워커를 유지하는 것이 아니라, 필요한 만큼만 사용해 비용과 성능을 동시에 최적화합니다.
4Spot Instance 사용이 적합하지 않은 작업은?
✅ 정답: ①
Spot Instance는 클라우드 제공사가 필요할 때 회수(중단)할 수 있습니다. 실시간 스트리밍처럼 중단이 허용되지 않는 서비스에는 On-Demand 인스턴스를 써야 합니다. 배치 잡이나 체크포인트를 사용하는 ML 학습은 중단 후 재시작이 가능해 Spot이 적합합니다.
5클러스터 정책(Cluster Policy)이 해결하는 문제는?
✅ 정답: ③
클러스터 정책은 관리자가 허용 가능한 인스턴스 타입, 최대 워커 수, 자동 종료 시간 등을 미리 정의하는 기능입니다. 개발자가 실수로 고비용 클러스터를 만들거나 방치하는 것을 방지해 조직 전체의 비용을 관리합니다.
