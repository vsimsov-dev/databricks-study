벡터 DB와 임베딩 개념

의미 기반 검색의 핵심 기술

⏱ 학습 시간: 약 10분 📝 퀴즈: 5문제 🔄 복습: 4문제
오늘의 핵심 개념

어제 RAG의 5단계 작동 원리를 배우며 "임베딩"과 "벡터 DB"라는 단어가 등장했습니다. 오늘은 이 두 부품을 조금 더 자세히 들여다봅니다. RAG가 "질문과 의미가 비슷한 문서를 찾아온다"고 했는데, 컴퓨터는 애초에 글자를 읽을 줄 모릅니다. 그래서 글의 의미를 숫자로 바꾸는 작업이 필요하고, 그 결과물을 저장하고 빠르게 비교하는 저장소가 필요합니다. 그것이 각각 임베딩(Embedding)과 벡터 DB(Vector Database)입니다.

🔢 임베딩이란? — 의미를 숫자 좌표로 바꾸는 번역기

임베딩은 단어나 문장을 수백~수천 개의 숫자로 이루어진 목록(벡터)으로 변환하는 과정입니다. 사람이 "이 영화는 액션과 로맨스가 반반 섞였다"처럼 취향을 좌표로 표현하듯, AI는 문장의 의미를 좌표(숫자 배열)로 표현합니다. 중요한 건 의미가 비슷한 문장일수록 벡터 값도 서로 가깝다는 점입니다.

"열접착 강도 기준"
→
[0.82, -0.15, 0.44, 0.09, ...]
"heat seal strength"
→
[0.79, -0.18, 0.41, 0.11, ...]
"오늘 점심 메뉴"
→
[-0.31, 0.67, -0.05, 0.88, ...]

💡 표현은 다르지만 의미가 같은 "열접착 강도 기준"과 "heat seal strength"는 벡터 값이 서로 가깝습니다. 반면 의미가 다른 "오늘 점심 메뉴"는 값이 멀리 떨어집니다. 이렇게 단어가 아니라 의미로 검색할 수 있게 됩니다.

📏 벡터 유사도 — 얼마나 "가까운가"를 재는 방법

벡터끼리 거리를 재는 대표적인 방법이 코사인 유사도(Cosine Similarity)입니다. 두 벡터가 가리키는 방향이 얼마나 비슷한지를 -1~1 사이 숫자로 나타내며, 1에 가까울수록 의미가 유사하다는 뜻입니다. 지도에서 두 위치 사이의 거리를 재듯, 벡터 공간에서 "질문 벡터"와 가장 가까운 "문서 벡터"를 찾는 것이 검색의 핵심입니다.

🗄️ 벡터 DB — 일반 데이터베이스와 무엇이 다른가?

구분 일반 DB (키워드 검색) 벡터 DB (의미 검색)
검색 기준 ❌ 정확히 일치하는 단어 ✅ 의미가 유사한 내용
동의어 처리 ❌ "열접착"과 "heat seal" 못 찾음 ✅ 같은 의미로 인식
저장 데이터 🔧 텍스트, 숫자, 날짜 등 🔧 임베딩 벡터(숫자 배열)
대표 예시 MySQL, SQL Server 검색 Databricks Vector Search, Pinecone

🏭 Databricks Vector Search 인덱스 유형

1

Delta Sync Index

Delta 테이블과 자동으로 동기화되는 인덱스. 원본 테이블에 새 문서가 추가되면 벡터 인덱스도 자동 갱신됩니다. 대부분의 실무 시나리오에 적합합니다.

2

Direct Access Index

API로 벡터를 직접 넣고 빼는 인덱스. 실시간으로 벡터를 세밀하게 제어해야 하는 고급 시나리오에 사용합니다.

# 텍스트를 임베딩 벡터로 변환하는 개념 코드 from databricks.vector_search.client import VectorSearchClient vs_client = VectorSearchClient() # Delta 테이블 기반으로 Vector Search 인덱스 생성 index = vs_client.create_delta_sync_index( endpoint_name="pp-docs-endpoint", source_table_name="polymer_tech.docs.pp_spec_chunks", index_name="polymer_tech.docs.pp_spec_index", embedding_source_column="chunk_text", embedding_model_endpoint_name="databricks-bge-large-en" )

🧪 팀에서 벡터 DB를 쓰면?

고분자 제품 개발 업무에서는 같은 개념도 문서마다 표현이 조금씩 다릅니다. "열접착 강도", "히트실 강도", "heat seal strength"가 같은 시험 항목을 가리키는 경우가 많습니다. 임베딩 기반 벡터 검색을 쓰면 정확한 용어를 몰라도 의미로 문서를 찾을 수 있습니다. 안전환경 업무에서도 SDS 문서의 표현이 회사마다 달라도 "피부 접촉 시 조치사항"처럼 자연어로 질문하면 관련 문단을 바로 찾아낼 수 있습니다.

💡 실무 적용 아이디어

배터리 파우치용 CPP 규격서, 압출코팅 PP 시험 성적서를 임베딩해 벡터 DB에 저장해두면, "라미네이트 접착력이 기준 미달일 때 확인할 항목"처럼 정확한 문서명을 몰라도 의미 기반으로 검색해 관련 규격 문단을 즉시 찾을 수 있습니다.

🔑 핵심 용어 카드

임베딩(Embedding)
텍스트의 의미를 숫자 벡터로 변환하는 과정. 의미가 비슷하면 벡터 값도 비슷함.
벡터(Vector)
여러 개의 숫자로 이루어진 배열. 임베딩의 결과물이며 공간상의 좌표로 볼 수 있음.
코사인 유사도
두 벡터의 방향이 얼마나 비슷한지 -1~1 값으로 측정. 1에 가까울수록 의미가 유사.
벡터 DB
임베딩 벡터를 저장하고 유사도 기준으로 빠르게 검색하는 전용 데이터베이스.
Delta Sync Index
Delta 테이블과 자동 동기화되는 Databricks Vector Search 인덱스 유형.
📌 한 줄 요약

임베딩은 의미를 숫자 벡터로 바꾸는 번역기이고, 벡터 DB는 그 벡터를 저장해 "의미가 비슷한 것"을 빠르게 찾아주는 저장소입니다.

오늘의 퀴즈 — 5문제
1임베딩(Embedding)이 하는 역할로 가장 알맞은 것은?
✅ 정답: ③ — 임베딩은 텍스트(단어, 문장, 문서)를 수백~수천 개의 숫자로 이루어진 벡터로 변환하는 과정입니다. 이 벡터가 텍스트의 의미를 수치로 표현합니다.
2"열접착 강도"와 "heat seal strength"처럼 표현이 다른데도 임베딩 벡터가 서로 가까운 이유는?
✅ 정답: ① — 임베딩은 단어 자체가 아니라 의미를 벡터로 표현하므로, 표현이나 언어가 달라도 의미가 같으면 벡터 값이 서로 가깝게 위치합니다. 이 원리 덕분에 동의어·다국어 검색이 가능합니다.
3코사인 유사도(Cosine Similarity)가 측정하는 것은?
✅ 정답: ② — 코사인 유사도는 두 벡터 사이의 방향이 얼마나 비슷한지를 -1~1 사이 값으로 나타냅니다. 1에 가까울수록 의미적으로 유사한 문서라는 뜻입니다.
4일반 키워드 검색 DB와 벡터 DB의 가장 큰 차이는?
✅ 정답: ④ — 일반 DB의 키워드 검색은 정확히 일치하는 단어가 있어야 찾아지지만, 벡터 DB는 임베딩된 의미를 기준으로 검색하므로 동의어나 다른 표현이어도 관련 문서를 찾을 수 있습니다.
5Databricks Vector Search의 Delta Sync Index가 갖는 특징은?
✅ 정답: ② — Delta Sync Index는 원본 Delta 테이블과 자동으로 동기화됩니다. 새 문서가 테이블에 추가되면 벡터 인덱스도 자동으로 갱신되어 별도의 수동 작업 없이 최신 상태를 유지합니다.
🔄 어제 배운 내용 복습 — RAG란? 엔터프라이즈에서 왜 쓰는가?
1RAG(Retrieval-Augmented Generation)의 기본 개념으로 올바른 것은?
✅ 정답: ② — RAG는 검색(Retrieval)과 생성(Generation)을 결합해, AI가 답하기 전에 관련 문서를 먼저 찾아 그 내용을 근거로 답변하는 방식입니다.
2RAG가 해결해주는 LLM의 대표적인 한계 두 가지는?
✅ 정답: ④ — RAG는 회사 내부 문서·최신 정보를 AI에 주입하고, 검색된 문서를 근거로 답하게 해 환각(사실이 아닌 내용을 그럴듯하게 만드는 현상)을 줄여줍니다.
3긴 문서를 500~1000자 단위로 잘라 저장하는 RAG의 전처리 단계를 무엇이라고 부르나요?
✅ 정답: ① — LLM은 한 번에 처리할 수 있는 텍스트 길이에 제한이 있어, 긴 문서를 청크(Chunk) 단위로 잘라 검색·전달에 사용합니다.
4RAG의 5단계(수집→분할→임베딩→검색→생성) 흐름에서, 사용자가 질문했을 때 가장 먼저 일어나는 일은?
✅ 정답: ③ — 사용자가 질문하면 그 질문도 임베딩되어 벡터로 변환되고, 벡터 DB에서 가장 유사한 문서 조각을 검색한 뒤 그 내용을 LLM에 전달해 답변을 생성합니다.
