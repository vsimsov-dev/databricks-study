Day 6 · 분산처리 엔진

Spark란? 왜 빠른가?

분산 처리·인메모리·지연 실행의 비밀

⏱ 학습 시간: 약 10분 📝 퀴즈: 5문제 🔄 복습: 4문제
오늘의 개념

엑셀로 수백만 행의 데이터를 열면 컴퓨터가 멈춰버린 경험, 있으신가요? 고분자 제품 개발을 하다 보면 물성 측정 데이터, 압출 공정 로그, 시험 성적서 등 수많은 데이터가 쌓입니다. 이 데이터들이 수억 건으로 늘어나면 일반 도구로는 감당이 안 됩니다.

Apache Spark는 이 문제를 해결하기 위해 탄생한 분산 처리 엔진입니다. 데이터를 여러 컴퓨터에 나눠서 동시에 처리하고, 결과를 메모리에 올려두기 때문에 전통적인 방식보다 수십~수백 배 빠릅니다. Databricks는 Spark를 핵심 엔진으로 사용하는 플랫폼이에요.

🏭 비유: 공장 라인 vs 1인 작업

기존 데이터 처리를 "혼자 100개 필름 롤을 검사하는 것"에 비유한다면, Spark는 "100명이 동시에 1개씩 나눠 검사하는 컨베이어 벨트 라인"입니다. 같은 작업이지만 속도가 완전히 달라지죠.

⚡ 비밀 1 — 인메모리(In-Memory) 처리

전통적인 Hadoop MapReduce는 각 단계 결과를 디스크에 저장한 뒤 다음 단계를 실행했습니다. 디스크 I/O는 메모리 접근보다 약 100배 느립니다. Spark는 중간 결과를 메모리(RAM)에 유지하면서 연산을 이어가기 때문에 훨씬 빠릅니다.

🔬 고분자 업무 적용 예시 PP 필름의 인장강도·신율·열수축 등 물성 데이터를 수년치 분석할 때, 중간 필터링 결과를 매번 파일로 저장하지 않고 메모리에서 바로 다음 계산으로 넘기는 방식으로 분석 시간을 크게 줄일 수 있습니다.

🦋 비밀 2 — 지연 실행(Lazy Evaluation)

Spark는 코드를 작성해도 즉시 실행하지 않습니다. 대신 "어떤 작업을 할 건지"의 실행 계획(Logical Plan)만 쌓아두다가, 실제 결과가 필요한 시점에 한 번에 최적화해서 실행합니다. 마치 배달 앱으로 여러 음식을 장바구니에 담다가 한 번에 주문하는 것과 같아요.

Python (PySpark) — 지연 실행 예시
# 아래 세 줄은 아직 실행되지 않음 (계획만 쌓임)
df = spark.read.parquet("/data/film_properties")
df_pp = df.filter(df.product_type == "CPP")
df_avg = df_pp.groupBy("grade").avg("tensile_strength")

# .show() 호출 시 비로소 실행 — 이 때 Spark가 계획 최적화 후 실행
df_avg.show()

🔀 비밀 3 — 분산 처리 (Partitioning)

Spark는 대용량 데이터를 파티션(Partition)이라는 조각으로 나누어 여러 Executor에 분배합니다. 각 Executor가 자신의 파티션만 병렬로 처리하기 때문에 전체 처리 시간이 극적으로 줄어듭니다.

항목 전통적 방식 (단일 서버) Spark (분산)
처리 단위 한 대 컴퓨터 수십~수백 대 병렬
중간 결과 디스크 저장 메모리 유지
실행 방식 즉시 실행 지연 실행 (최적화)
대용량 데이터 OOM / 타임아웃 안정적 처리
비용 구조 고성능 서버 1대 필요 일반 서버 여러 대 활용

🔑 RDD → DataFrame → Dataset 진화

Spark는 세 가지 데이터 추상화를 제공합니다. 현재 실무에서는 DataFrame API를 가장 많이 사용하며, SQL과 유사한 문법으로 데이터를 다룰 수 있습니다. Databricks에서는 이 DataFrame이 Delta Lake 테이블로 자연스럽게 연결됩니다.

1

RDD (Resilient Distributed Dataset)

Spark 초기 핵심 개념. 분산된 데이터 컬렉션. 유연하지만 코드가 복잡하고 최적화 어려움.

2

DataFrame

행·열 구조의 분산 테이블. SQL과 거의 동일한 문법. 자동 쿼리 최적화(Catalyst Optimizer) 적용. 현재 주력.

3

Dataset (Scala/Java 전용)

DataFrame + 타입 안전성. Python에서는 DataFrame = Dataset으로 통일. PySpark 사용자는 DataFrame만 알면 충분.

Driver
Spark 클러스터의 지휘자. 사용자 코드를 받아 실행 계획을 만들고 Executor들에게 작업을 배분합니다.
Executor
실제 데이터를 처리하는 일꾼. 각자 맡은 파티션을 메모리에서 계산하고 결과를 Driver에게 반환합니다.
Partition
대용량 데이터를 나눈 조각. 각 파티션은 독립적으로 병렬 처리됩니다. 파티션 수 = 병렬 처리 단위.
Catalyst Optimizer
Spark 내부 쿼리 최적화 엔진. 지연 실행 덕분에 불필요한 연산을 제거하고 최적 실행 계획을 자동으로 수립합니다.
Shuffle
파티션 간 데이터 재배치. groupBy, join 시 발생하며 네트워크 비용이 크기 때문에 최소화가 성능 최적화의 핵심입니다.
Spark는 분산 처리 + 인메모리 + 지연 실행이라는 세 가지 비밀로
대용량 데이터를 기존 방식보다 수십~수백 배 빠르게 처리합니다.
오늘의 퀴즈 — 5문제
1Spark가 Hadoop MapReduce보다 빠른 가장 큰 이유는 무엇인가요?
✅ 정답: ② — Spark는 중간 연산 결과를 디스크에 저장하지 않고 메모리(RAM)에 유지합니다. 메모리 접근 속도는 디스크보다 약 100배 빠르기 때문에 여러 단계의 처리가 이어질수록 속도 차이가 극적으로 커집니다.
2Spark의 "지연 실행(Lazy Evaluation)"이란 무엇을 의미하나요?
✅ 정답: ③ — Spark는 filter, select, groupBy 같은 변환(Transformation) 코드를 작성해도 즉시 실행하지 않습니다. 실행 계획만 내부에 쌓다가 .show(), .collect() 같은 Action이 호출될 때 Catalyst Optimizer가 전체 계획을 최적화한 뒤 실행합니다.
3Spark 클러스터에서 "Driver"의 역할로 가장 적합한 설명은?
✅ 정답: ① — Driver는 Spark 애플리케이션의 두뇌입니다. 사용자가 작성한 코드를 Task로 변환하고, 클러스터 내 여러 Executor에게 배분하며, 처리 완료된 결과를 수집합니다. Executor들이 실제 데이터를 처리하는 일꾼이라면, Driver는 그 일꾼들을 조율하는 관리자입니다.
4Spark에서 "파티션(Partition)"이 중요한 이유는 무엇인가요?
✅ 정답: ④ — 파티션은 Spark 병렬 처리의 핵심 단위입니다. 데이터를 파티션으로 나누면 각 Executor가 자신의 파티션만 독립적으로 처리할 수 있어, 전체 처리 시간이 파티션 수에 비례하여 단축됩니다.
5다음 중 현재 Spark 실무에서 가장 많이 사용하는 데이터 추상화 API는?
✅ 정답: ② — DataFrame은 행·열 구조의 분산 테이블로, SQL과 거의 동일한 문법을 제공합니다. Catalyst Optimizer가 자동으로 쿼리를 최적화하기 때문에 RDD보다 코드가 단순하고 성능도 좋습니다. Databricks에서는 이 DataFrame이 Delta Lake 테이블과 자연스럽게 연동됩니다.
🔄 어제 배운 내용 복습 — SQL로 데이터 조회하기
1SQL에서 특정 조건을 만족하는 행만 필터링할 때 사용하는 절은?
✅ 정답: ③ — WHERE 절은 개별 행 단위로 조건을 적용하여 원하는 데이터만 필터링합니다. 예: WHERE product_type = 'CPP' AND tensile_strength > 150. HAVING은 GROUP BY 이후 집계 결과에 조건을 적용할 때 사용합니다.
2SQL에서 두 테이블의 공통 키를 기준으로 데이터를 합치는 명령어는?
✅ 정답: ① — JOIN은 공통 키(Key) 컬럼을 기준으로 두 테이블의 행을 연결합니다. INNER JOIN은 양쪽에 모두 존재하는 행만, LEFT JOIN은 왼쪽 테이블 전체를 기준으로 연결합니다. UNION은 두 쿼리 결과를 위아래로 합치는 명령어입니다.
3GROUP BY와 함께 사용하며, 집계 결과에 조건을 거는 SQL 절은?
✅ 정답: ④ — HAVING은 GROUP BY로 집계된 결과에 조건을 적용합니다. 예: GROUP BY grade HAVING AVG(tensile_strength) > 200. WHERE는 GROUP BY 이전에 행 단위 필터링에 사용하고, HAVING은 GROUP BY 이후 집계 결과에 사용한다는 차이가 있습니다.
4다음 SQL 문에서 AVG(tensile_strength)가 하는 역할은?
SELECT grade, AVG(tensile_strength) FROM film_data GROUP BY grade
✅ 정답: ② — AVG()는 평균 집계 함수입니다. GROUP BY grade와 함께 사용되므로 grade별로 그룹을 나눈 뒤 각 그룹 내 tensile_strength의 평균값을 계산합니다. 예: T200 등급 평균 인장강도, T300 등급 평균 인장강도처럼 등급별 물성 평균을 한 번에 구할 수 있습니다.
