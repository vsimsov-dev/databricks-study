Day 11 · AI/RAG

RAG란? 엔터프라이즈에서 왜 쓰는가?

검색 증강 생성으로 AI에 지식 주입하기

⏱ 학습 시간: 약 10분 📝 퀴즈: 5문제 🔄 복습: 4문제
오늘의 핵심 개념

어제 LLM(대형 언어 모델)을 배웠습니다. ChatGPT나 Claude 같은 AI는 방대한 텍스트로 학습되어 있지만, 한 가지 결정적인 한계가 있습니다. 바로 "학습 데이터가 끊기는 시점"과 "회사 내부 자료를 모른다"는 것입니다. 예를 들어 "우리 회사 최신 PP 규격서의 인장강도 기준은?" 이라고 물으면 AI는 답을 모릅니다. 이 문제를 해결하는 기술이 바로 RAG(Retrieval-Augmented Generation)입니다.

RAG는 "검색(Retrieval) + AI 생성(Generation)"을 결합한 방식입니다. AI가 답하기 전에 먼저 관련 문서를 찾아서 읽고, 그 내용을 바탕으로 답변을 생성합니다. 도서관 사서가 책을 찾아다 주면, 전문가가 그 책을 읽고 요약해 주는 것과 같습니다.

⚡ RAG 작동 흐름
사용자 질문
→
문서 검색
(Retrieval)
→
관련 문서
조각 추출
→
LLM 생성
(Generation)
→
정확한 답변

📚 왜 일반 LLM만으로는 부족한가?

LLM은 학습된 시점까지의 공개 데이터만 알고 있습니다. 회사 내부 기술 규격, 최신 시험 성적서, 고객 요청 사항 등은 당연히 모릅니다. 또한 잘못된 정보를 그럴듯하게 만들어내는 "환각(Hallucination)" 문제도 있습니다. RAG는 이 두 가지를 동시에 해결합니다.

구분 일반 LLM RAG 적용 LLM
지식 범위 ❌ 학습 데이터까지만 ✅ 실시간 내부 문서 포함
최신성 ❌ 수개월~수년 지연 ✅ 최신 파일 즉시 반영
환각 위험 ❌ 높음 ✅ 출처 기반으로 낮아짐
회사 내부 정보 ❌ 모름 ✅ 접근 가능
구축 비용 ✅ 낮음 (그냥 쓰면 됨) 🔧 문서 파이프라인 필요

🔍 RAG의 5단계 작동 원리

1

문서 수집 및 청크(Chunk) 분할

PDF, Word, 웹페이지 등 문서를 수집하고 500~1000자 단위로 잘게 자릅니다. 너무 긴 문서는 한꺼번에 AI에 넣을 수 없기 때문입니다.

2

임베딩(Embedding) — 의미를 숫자로 변환

각 청크를 수백~수천 개의 숫자(벡터)로 변환합니다. 비슷한 내용은 비슷한 숫자 값을 가집니다. (내일 더 자세히 배울 예정이에요!)

3

벡터 DB에 저장

변환된 벡터를 벡터 DB에 저장합니다. 이후 검색 시 의미적으로 유사한 문서를 빠르게 찾을 수 있습니다.

4

질문 → 유사 문서 검색

사용자가 질문하면 질문도 벡터로 변환하고, DB에서 가장 유사한 문서 조각 3~5개를 꺼냅니다.

5

LLM에게 문서 + 질문 전달 → 답변 생성

검색된 문서를 컨텍스트로 붙여서 LLM에 전달합니다. AI는 이 문서를 읽고 근거 있는 답변을 생성합니다.

🏭 Databricks에서 RAG 구현 예시

Databricks는 RAG 파이프라인 전체를 한 플랫폼에서 구성할 수 있습니다. Delta Lake에 문서를 저장하고, MLflow로 실험을 관리하며, Vector Search로 빠른 검색을 제공합니다.

# Databricks RAG 구현 예시 (개념 코드) from databricks.vector_search.client import VectorSearchClient # 1. 문서 임베딩 후 Vector Search 인덱스에 저장 vs_client = VectorSearchClient() index = vs_client.get_index( endpoint_name="pp-docs-endpoint", index_name="catalog.schema.pp_spec_index" ) # 2. 질문으로 유사 문서 검색 question = "레트로트용 CPP의 열접착 강도 기준은?" results = index.similarity_search( query_text=question, num_results=3 ) # 3. 검색된 문서 + 질문 → LLM에 전달하여 답변 생성 context = "\n".join([r['text'] for r in results]) answer = llm.generate(f"컨텍스트: {context}\n\n질문: {question}")

🧪 팀에서 RAG를 쓰면?

고분자 제품 개발 업무에서는 수많은 규격서, 시험 성적서, 고객 요청 사양이 쌓입니다. RAG를 적용하면 "레트로트용 CPP 규격의 열접착 온도 조건은?", "EAA 코팅 두께 기준이 어느 문서에 있지?" 같은 질문에 AI가 내부 문서를 뒤져 즉시 답할 수 있습니다. 안전환경 업무에서도 화학물질 SDS(물질안전보건자료) 전체를 RAG로 구성하면 "이 물질의 응급 처치법은?" 같은 질문에 빠르게 대응할 수 있습니다.

💡 실무 적용 아이디어

팀에서 관리하는 PP·PE 제품 규격서 PDF를 Delta Lake에 적재 → 청크 분할 → Databricks Vector Search에 인덱싱하면, "배터리 파우치용 CPP의 방습성 시험 기준"처럼 구체적인 기술 질문을 자연어로 검색할 수 있습니다. 기존에 사람이 직접 찾던 시간을 AI가 단 몇 초로 단축합니다.

🔑 핵심 용어 카드

RAG
Retrieval-Augmented Generation. 검색과 AI 생성을 결합한 기술. 내부 문서를 AI에 주입하는 방법.
청크(Chunk)
긴 문서를 작은 조각으로 자른 단위. 보통 500~1000자 크기로 분할.
임베딩(Embedding)
텍스트를 숫자 벡터로 변환하는 과정. 의미가 비슷한 텍스트는 비슷한 벡터 값을 가짐.
벡터 DB
임베딩 벡터를 저장하고 유사도 검색을 빠르게 수행하는 특수 데이터베이스.
환각(Hallucination)
LLM이 사실이 아닌 내용을 그럴듯하게 만들어 내는 현상. RAG로 크게 줄일 수 있음.
📌 한 줄 요약

RAG는 AI가 모르는 내부 문서를 실시간으로 검색해 답변에 활용하는 기술로, LLM의 환각·정보 시한 문제를 동시에 해결합니다.

오늘의 퀴즈 — 5문제
1RAG(Retrieval-Augmented Generation)에서 "Retrieval"이 의미하는 것은?
✅ 정답: ② — Retrieval은 "검색·인출"을 뜻합니다. RAG에서는 사용자 질문과 의미적으로 유사한 문서 조각을 벡터 DB에서 꺼내오는 단계입니다. 이 문서가 LLM에 전달되어 답변 생성의 근거가 됩니다.
2RAG가 일반 LLM 단독 사용보다 유리한 가장 큰 이유 두 가지는?
✅ 정답: ③ — RAG의 핵심 이점은 ① 회사 내부 문서나 최신 데이터를 AI에 주입할 수 있고, ② 문서 근거를 바탕으로 답하므로 환각(허구 정보 생성)이 크게 줄어든다는 점입니다.
3RAG 파이프라인에서 "청크(Chunk) 분할"을 하는 이유는?
✅ 정답: ① — LLM은 한 번에 처리할 수 있는 텍스트 길이(컨텍스트 윈도우)에 제한이 있습니다. 또한 검색 정확도를 높이기 위해 관련 부분만 추출하여 전달하는 것이 효율적입니다. 그래서 긴 문서를 500~1000자 단위로 잘라 사용합니다.
4임베딩(Embedding)에 대한 설명으로 올바른 것은?
✅ 정답: ④ — 임베딩은 텍스트의 의미를 수백~수천 개의 숫자(벡터)로 표현합니다. "열접착 강도"와 "heat seal strength"처럼 다른 표현이지만 의미가 유사하면 비슷한 벡터 값을 가집니다. 이를 통해 의미 기반 검색이 가능합니다.
5Databricks에서 RAG 파이프라인 구축 시, 문서 임베딩 벡터를 저장하고 유사도 검색을 수행하는 컴포넌트는?
✅ 정답: ② — Databricks Vector Search는 임베딩 벡터를 저장하고 의미 기반 유사도 검색을 고속으로 수행하는 전용 서비스입니다. Delta Lake와 통합되어 문서 업데이트 시 인덱스를 자동으로 동기화할 수도 있습니다.
🔄 어제 배운 내용 복습 — AI/ML 기초 · LLM과 파운데이션 모델
1LLM(Large Language Model)이 텍스트를 생성하는 기본 원리는?
✅ 정답: ③ — LLM은 수천억 개의 텍스트 패턴을 학습해 "이 단어 다음에 어떤 단어가 올 확률이 높은가"를 예측하여 자연스러운 텍스트를 생성합니다. 실시간 검색이나 계산이 아닌 학습된 패턴에서 나오는 것입니다.
2파운데이션 모델(Foundation Model)의 특징으로 올바른 것은?
✅ 정답: ① — 파운데이션 모델은 수조 개의 텍스트/데이터로 대규모 사전 학습(pre-training)을 거쳐 번역, 요약, 코딩, 질문 답변 등 다양한 태스크에 활용 가능합니다. GPT-4, Claude, Gemini 등이 대표적입니다.
3파인튜닝(Fine-tuning)이 필요한 상황으로 가장 적합한 것은?
✅ 정답: ④ — 파인튜닝은 도메인 특화 데이터로 기존 모델을 추가 학습시키는 과정입니다. PP 인장강도, 열접착 규격처럼 일반 AI가 잘 모르는 전문 영역에 특화시킬 때 필요합니다. 범용 태스크는 기본 LLM으로 충분합니다.
4Databricks에서 다양한 LLM을 실험하고 배포할 수 있게 해주는 기능은?
✅ 정답: ② — Databricks의 Model Serving과 Foundation Model APIs를 통해 Meta Llama, Mistral 등 다양한 오픈소스 LLM을 API 형태로 쉽게 호출하고 비교 실험할 수 있습니다. MLflow와 연동해 모델 버전도 관리됩니다.
