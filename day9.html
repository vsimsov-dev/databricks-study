데이터 파이프라인이란?

데이터 파이프라인(Data Pipeline)은 원본 데이터를 수집해서 분석 가능한 형태로 전달하는 일련의 자동화된 처리 과정입니다. 공장의 생산 라인처럼, 원자재(원시 데이터)가 들어와 여러 공정을 거쳐 완제품(분석 데이터)이 나오는 구조입니다. 이 과정이 자동화되어 있어야 매일 반복 실행되어도 사람이 수동으로 개입할 필요가 없습니다.

ETL vs ELT — 무엇이 다른가?

데이터를 처리하는 방식은 크게 두 가지로 나뉩니다. ETL(Extract-Transform-Load)과 ELT(Extract-Load-Transform)입니다. 가장 큰 차이는 변환(Transform) 작업이 적재 전에 일어나느냐, 적재 후에 일어나느냐입니다.

📦 ETL
추출 → 변환 → 적재
  • 변환 후 정제된 데이터만 적재
  • 전통적인 데이터 웨어하우스 방식
  • 원시 데이터가 저장소에 남지 않음
  • 변환 로직 수정 시 처음부터 재처리
🚀 ELT
추출 → 적재 → 변환
  • 원시 데이터를 먼저 저장(Bronze)
  • 레이크하우스·클라우드 환경에 적합
  • 원시 데이터 보존으로 재처리 용이
  • 변환 로직을 나중에 바꿀 수 있음
💡 Databricks는 ELT 방식을 권장합니다. 메달리온 아키텍처(Bronze → Silver → Gold)가 바로 ELT 패턴의 실제 구현입니다.

Databricks Workflows란?

Databricks Workflows는 Databricks 플랫폼에 내장된 파이프라인 오케스트레이션 도구입니다. 여러 노트북이나 Python 스크립트를 순서대로(또는 병렬로) 실행하고, 스케줄을 지정해 자동 실행하며, 실패 시 알림을 보내주는 기능을 제공합니다.

⏰

스케줄링

매일, 매시간, 특정 시각 등 원하는 주기로 파이프라인을 자동 실행할 수 있습니다. Cron 표현식도 지원합니다.

🔗

의존성 관리

Task A가 완료된 후 Task B를 실행하는 식으로 작업 간 순서와 조건을 정의할 수 있습니다.

📡

모니터링·알림

실행 성공/실패 이력을 한눈에 확인하고, 실패 시 이메일·Slack 알림을 자동으로 받을 수 있습니다.

🔄

재시도·복구

특정 Task가 실패하면 자동으로 재시도하거나, 실패한 Task부터 이어서 재실행할 수 있습니다.

고분자팀 파이프라인 예시

🏭 PP 필름 물성 데이터 자동 수집 파이프라인 (매일 오전 6시 자동 실행)
  • Task 1 — 수집(Extract): ERP에서 전날 PP 필름 생산 데이터와 물성 측정 CSV를 Bronze 레이어로 적재
  • Task 2 — 정제(Transform to Silver): 이상값 제거, 중복 삭제, 컬럼명 통일 후 Silver 레이어에 저장
  • Task 3 — 집계(Transform to Gold): 그레이드별 당일 평균 물성 집계, KPI 지표 계산 후 Gold 레이어에 저장
  • Task 4 — 알림: 처리 완료 후 팀 채널에 요약 메시지 전송. 오류 발생 시 즉시 담당자에게 알림

오늘의 퀴즈
1ETL과 ELT의 가장 핵심적인 차이는 무엇인가요?
✅ 정답: ①
ETL(Extract-Transform-Load)은 데이터를 추출해 변환한 뒤 적재합니다. ELT(Extract-Load-Transform)는 먼저 원시 데이터를 적재(Bronze)한 후 변환합니다. Databricks 메달리온 아키텍처는 ELT 방식입니다.
2Databricks Workflows의 기능으로 옳지 않은 것은?
✅ 정답: ④
Databricks Workflows는 파이프라인의 스케줄링, 의존성 관리, 모니터링, 알림, 재시도 기능을 제공합니다. ML 모델의 예측 정확도를 자동으로 높이는 기능은 Workflows의 역할이 아닙니다.
3Databricks가 ETL보다 ELT 방식을 권장하는 가장 큰 이유는?
✅ 정답: ③
ELT 방식에서는 원시 데이터를 먼저 Bronze에 저장하기 때문에, 변환 로직에 오류가 있어도 원본부터 다시 처리할 수 있습니다. 메달리온 아키텍처가 ELT 패턴의 실제 구현입니다.
4고분자팀에서 "매일 오전 6시에 전날 PP 필름 물성 데이터를 자동 수집·정제·집계하는 파이프라인"을 구성하려 합니다. 이를 위해 가장 적합한 Databricks 기능은?
✅ 정답: ②
Databricks Workflows는 파이프라인의 스케줄 실행, 여러 Task 간 의존성 관리, 모니터링을 제공합니다. 매일 정해진 시각에 자동으로 수집→정제→집계를 실행하는 용도에 가장 적합합니다.
5데이터 파이프라인에서 "의존성 관리(Dependency Management)"란 무엇인가요?
✅ 정답: ①
파이프라인에서 의존성 관리란 Task 간 실행 순서와 조건을 정의하는 것입니다. 예를 들어 "Bronze 적재 Task가 완료된 후에만 Silver 정제 Task를 실행"처럼 선행 작업의 성공 여부에 따라 다음 작업 실행을 제어합니다.
